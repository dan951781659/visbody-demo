## 业务决定（已确认，后台部分尚未实现）

- 实际场景：设备测量完成 → 扫码进入本次报告详情 → 可查看对应 AI 解读；填写健康档案后可生成训练大纲。
- 基础测量报告正常可查看。付费服务仅为 AI 报告解读与个性化训练大纲，二者独立，训练不以 AI 解读为前置条件。
- 当前 B 端开通服务并生成后，C 端可直接查看。
- 未来保留 B 端提供服务模式，并允许 B 端配置由 C 端付费。已经生成的服务可直接查看，只有尚未生成的服务需要按权益及付费模式判断，不能重复收费。
- C 端付费后的相关服务信息需要 B 端可见；真实支付、生成、B/C 同步和权限控制仍属于未来后台实现。
- 权益、生成内容与来源测量要分别管理；不要仅凭全局 AI 开关或演示大纲判定用户已有结果。

## 原版首页规则（v0.2.14，当前）

- 首页定位为多次测量后的纵向综合总览；设备扫码、测量完成和报告生成通知仍直达绑定的本次报告，避免首页与单次报告重复。
- 默认统计最近使用设备族、同算法口径下最近 7 个有效测量批次，显示真实起止日期；不足 7 次按实际次数展示。指标趋势读取该指标最近 7 条有效且可比记录。
- 首页顺序：身体状态总览 → 我的服务 → 需要关注与已有改善 → 双次模拟形态对比 → 指标变化 → 最近报告入口；核心指标和历史变化已合并为一个趋势模块。
- 身体状态总览显示覆盖范围、设备和各模块覆盖次数；严格区分“设备支持”“本次已测”“最近覆盖”“设备不支持”，未测不得判定为正常。
- 关注项按风险等级优先，再按持续/新增状态和时间排序；至少 3 次可比记录才判断持续关注或持续改善，少量记录按最新状态降级展示。
- AI 解读按报告归属判断当前/历史来源；训练大纲按用户当前服务归属，不要求先生成 AI 解读。当前主 Demo 按用户要求固定展示二者均已生成的内存演示状态，不写入个人服务记录；旧四种隔离预览保留。
- 改善、持续关注、新增关注统计单位为模块，点击进入相应阶段详情筛选；详情中的七批测量时间线区分风险、关注、良好和未测，并可打开原始报告。
- 双模型为一份原始扫描资产的派生模拟，明确标注“模拟形态·交互演示”；支持并排/叠加、同步旋转缩放、视角切换、透明度和日期选择，不冒充真实两次扫描差异。
- 数字入场、指标底板弹性切换、曲线绘制/磁吸选点、章节定位及详情过渡已接入；返回保留首页滚动、趋势指标/选点和模型模式/日期/视角/暂停状态。系统减少动态效果下默认模型暂停。
- 当前 Demo 使用现有 M60 七模块和 7 批部分测量 Mock 验证兼容逻辑；M60S 九模块仅是 PRD 中的设备能力示例，真实能力矩阵与纵向聚合必须由后台提供。

## 原版首页历史规则（v0.2.0–v0.2.3，已由 v0.2.11 替代）

- 首页是身体概况总览。首屏以最近一次测量为准，模型、指标、摘要对应同一报告；历史区看变化，本期没有周汇总。
- 顺序：最近测量概况及首屏 3D → 独立 AI／训练服务 → 最多三项重点关注及可展开良好表现 → 四指标历史趋势。
- 不伪造日期、不用档案体重替代报告体重、不在删除后补回示例报告；同设备、同指标口径才能连成趋势。
- 移除首页固定 VISBODY＋WellnessHub 品牌栏，保留实色状态栏安全区；其他页面采用自己的标题。
- 两种服务各自显示已生成／尚未生成；**Demo 三态切换**（实际数据 / 已生成预览 / 未生成预览）用于预览空态与满态 UI，不改变真实服务数据。
- 历史变化首页固定展示近 7 次可比测量；点击区块或趋势卡进入 `#/history` 全参数列表（综合评分、体脂率、肌肉量、体重）。
- 四个只读内存演示入口：`#/preview/none/home` 等，规则不变。
- 模型约30秒一圈；拖动／缩放暂停，结束3秒后恢复；离屏及标签隐藏暂停；尊重减少动态效果。
- 多色语义：AI及脊柱紫色，训练及良好表现绿色，关注及体脂橙色，历史／颈部／平衡青蓝，体围／评分／体重品牌蓝。操作入口统一品牌蓝。
